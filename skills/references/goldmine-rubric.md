# Goldmine rubric (topic scouting)

A "goldmine" is a research target where (i) progress is machine-checkable, (ii) there is a credible tractability signal, and
(iii) even a partial result is publishable. The rubric exists because the 2025–26 record shows AI produced genuinely new
mathematics almost exclusively on problems with an exact verifier (Ramsey/Zarankiewicz bounds, packings, tensor ranks,
autocorrelation constants, finite-field Kakeya, OEIS conjectures) and produced embarrassing rediscoveries where the literature
check was weak.

## 1. Sources to mine (access method)

| Source | What it gives | Access |
|---|---|---|
| erdosproblems `data/problems.yaml` (github.com/teorth/erdosproblems) | 1200+ problems, `status`, `tags`, `prize`, `formal` (Lean link), `oeis`, `ai_attempts` | `git clone` into `.cache/sources/` (the website 403s scrapers) |
| Erdős AI wiki (same repo, wiki) | which problems AI attacked, and the recorded failures | WebFetch |
| DeepMind `formal-conjectures` | 2600+ Lean statements of open conjectures, tagged by area/MSC | `git clone` |
| AlphaEvolve repository of problems | 67 problems **with verifier code** and best-known constructions | `git clone` |
| Epoch FrontierMath: Open Problems | 50 tiered open problems, 5 AI-solved | web page |
| OEIS | sequences with keywords `hard`, `more`, `unkn`; "Conjecture:" lines in comments/formulas | `python -m harness lit search --engine oeis` / `oeis-conjectures` |
| Open Problem Garden | ~1000 problems by area | WebFetch/RSS |
| Kourovka Notebook | group theory problems | arXiv source |
| MathOverflow `open-problems` tag | community-curated, with discussion of partial progress | `python -m harness lit search --engine mo` |
| Ben Green's 100 open problems | additive combinatorics/analytic NT | PDF |
| Recent arXiv (`python -m harness lit search --engine arxiv --max 50 ... sort=submittedDate`) | **new techniques** that have not yet been applied to old problems | API |
| `library/rejected.jsonl`, `library/results.jsonl` | what past campaigns already dropped or finished | `python -m harness library check-rejected` |

Before scoring, run `python -m harness library check-rejected "<topic>"`; a hit disqualifies unless the reason has changed.

## 2. Scoring (0–3 each; weighted sum, max 33)

| # | Dimension | Weight | 0 | 3 |
|---|---|---|---|---|
| V | **Verifiability** — an exact verifier (certificate checker / exact scorer) exists or can be written in a day | ×4 | only human-readable proofs | verifier code exists (e.g. AlphaEvolve repo) |
| T | **Tractability signal** — recent progress, small gap between bounds, technique from the survey not yet applied, computational reach with 32 cores | ×3 | no movement in 20 years, no idea | progress in last 2 years and a concrete unused technique |
| N | **Novelty / impact** — open status confirmed, no recorded AI solution, cited/discussed, community cares | ×3 | obscure or possibly solved | listed open problem with prize/citations, `ai_attempts` empty or failed |
| P | **Partial-result publishability** — improving a constant, a new construction, a new family, or a rigorous negative result would be a paper | ×2 | all-or-nothing | any improvement publishable |
| I | **Interpretation clarity** — the statement is unambiguous or can be fixed precisely (definition unit tests) | ×1 | folklore statement with disputed reading | formal statement exists |
| L | **Literature risk (inverse)** — how likely the target is already solved but hard to find | ×1 | elementary Erdős-style NT (highest rediscovery risk) | niche computational problem with a tracked best-known value |
| F | **Fit** — the harness's strengths: search, exact computation, structured proof, multi-lens ideation | ×1 | needs deep theory only | search + short proof of the construction |

Any target with V = 0 needs explicit justification to survive (it can, e.g. a structural conjecture with strong numerical
falsification tests), and is capped at portfolio position ≥ 3.

## 3. Procedure

1. **Harvest** ≥ 30 candidates across ≥ 4 sources (cheap: titles + one line). Log every candidate in `portfolio.md` §Harvest.
2. **Triage** to ≤ 12 with the rubric (score each dimension with a one-line reason; no arithmetic in prose — compute the
   weighted sum in a script or a table generated by code).
3. **Pairwise tournament** among the top 12: for each pair, argue which is the better campaign target under the rubric and
   record the winner; rank by wins (Elo-style). This catches rubric blind spots.
4. **Cheap falsification of the premise** for the top 5: confirm the problem is still open *today* (erdosproblems status,
   formal-conjectures, arXiv search of the last 24 months, MathOverflow) and record the excerpts. Drop anything solved.
5. **Portfolio**: primary target + 2 backups with pivot triggers. Budgets: hours/tokens per phase; kill criteria (e.g. "no
   construction beating the known bound after 3 evolutionary runs of 200 generations", "no proof route survives falsification").

## 4. `portfolio.md` format

```markdown
# Portfolio — <campaign slug> (date)
## Harvest (N candidates)
| # | Candidate | Source | Status excerpt (with locator) |
## Rubric scores (top 12)
| Candidate | V | T | N | P | I | L | F | Weighted | Notes |
## Tournament ranking
1. ... (wins: 9/11)
## Selected target
- Statement (informal): ...
- Why goldmine: ...
- Verifier plan: ...
- Known best result (excerpt, source): ...
- Kill criteria: ...
- Backups: ...
```

## 5. Anti-patterns

- Choosing a famous problem for its fame (Riemann, Collatz, P vs NP): V = 0, T = 0.
- Choosing a problem because the model "remembers" a promising idea: memories are not evidence; put it through falsification.
- Ignoring `ai_attempts`/wiki records: if three systems already failed the same way, the route is dead unless you have a new lens.
- Trusting a status field without an excerpt and date.
